# 视觉指南与生图提示词模板

本文件管三件事：**角色怎么长**、**画面怎么排**、**给生图工具的中文提示词怎么填**。

配套资产在同目录上一级的 `assets/`，一律用**相对路径**引用。

---

## 0. 先定一条铁律：插画与文字分层

| 层 | 谁负责 | 为什么 |
|---|---|---|
| 角色画面 | 生图能力（WorkBuddy ImageGen 优先） | 画风、造型、氛围 |
| 中文文案、计数、来源、日期 | **排版模板**（`assets/templates/`） | 中文与数字由模板保证准确；数字必须可核对 |

**不要让生图模型写中文、写数字、画 logo。** 拿不到生图能力时，交文字胃＋排版模板，**不要假装图已经画好**。

---

## 1. 角色构成：主体按数据变，不是换名字

同一个模板套所有人 = 失败。角色必须从**这个人的实际偏好**长出来：

| 数据里的角色 | 变成画面里的 | 依据 |
|---|---|---|
| **主食**（最高频的那个） | 角色的**主体造型** | 具体餐品名 + 官方餐品图作造型参考 |
| **常点饮料** | 手里的**道具** | 具体饮料名（保留冰/热、无糖/含糖，别合并） |
| **常点配餐** | 身边的**伙伴** | 具体配餐名 |
| **时段** | **环境/光线**（早餐的清晨、夜间的暖光） | `segment_freq` 真的有 ≥3 笔才用 |

**没有依据的餐品不抢主视觉。**
**不要每个人都堆薯条**——薯条只在它真的进了这个人的偏好时才出现；否则它只是装饰，
而装饰**不构成口味证据**，也不该让人误以为这人爱吃薯条。

麦当劳元素优先从这些地方来：**包装、纸盘、纸袋、红黄配色、门店环境、金色拱形轮廓**。

## 2. 造型必须有官方依据（踩过的坑）

早期版本的「鱼堡」角色被画成了**尖顶包子**——因为提示词里只有「蒸包」。

**正确做法：把官方餐品图作为参考图一起给生图工具**（image-to-image），让造型对齐真餐品：

- 鱼堡 → `assets/brand/麦香鱼-官方餐品.png`
- 套餐形态 → `assets/brand/麦香鱼套餐-官方餐品.png`
- 配餐 → `assets/brand/薯条-官方餐品.png`（仅在确有依据时使用）

**金拱门一律用 `assets/brand/麦当劳官网标志.png` 原图合成**，不让模型画 logo。

## 3. 配色与字体

### 配色（**分两层，别混用**）

**第一层 · 旧 A/B/C 卡面色板。** 这是既有卡框/排版用色，**不是**新角色插画的硬约束：

| 用途 | 色值 |
|---|---|
| 主红 | `#DA291C` |
| 深红（描边/压底） | `#A8160C` |
| 主黄 | `#FFC72C` |
| 浅黄底 | `#FFF0C4` |
| 奶油白（卡面） | `#FFF9F1` |
| 暖纸底 | `#FAF6EE` |
| 墨色文字 | `#231F1C` |
| 次级文字 | `#7C7268` |

**第二层 · 角色插画的色系由所选美术方向定**（见 §6）。第二轮 D/E/F **已否决**（D 电光蓝/亮黄、E 冰蓝、F 雪白＋炭黑＋荧光黄），
第三轮 G/H/I 见 §6.3（G 浅天蓝、H 薄荷绿、I 淡桃粉；**I 已选定**，见 §6.4）。**角色色系不套卡面色板。**

> 旧文档里「**不许自创第三主色**」「**固定奶油白底**」这类约束，**仅适用于旧 A/B/C 卡面**，
> 对角色插画**不再生效**——否则各方向根本拉不开质感差异。
> 唯一仍然成立的硬要求：不用烂大街的紫色渐变；金拱门只用官方原图，不让模型画 logo。

### 字体层级（系统字体，不引外部字体）

| 层级 | 字体 | 用途 |
|---|---|---|
| 角色名/大标题 | 圆体优先：`Yuanti SC` → `PingFang SC` | 卡通感、加粗 |
| 正文 | `PingFang SC` | 说明、规则 |
| 计数/来源/编号 | 等宽：`SF Mono` → `Menlo` | 数字要能一眼核对 |

字号参考（375×500 的卡）：角色名 30–40px ／ 宣言 15–19px ／ 正文 11.5–13.5px ／ 脚注 9.5–10px。

## 4. 构图与文案位置

一张 375×500 的卡，只放**一个身份、一个笑点、一条撑得住的依据**：

1. **顶部**：方向标签 + 「虚构样例」标记（示例必须标）
2. **主视觉**：角色/场景，占 40%–50% 高度
3. **角色名**：最大字
4. **宣言**：一句话
5. **一条依据**：计数形态，例如「4 笔个人订单 · 麦香鱼 3 次」
6. **一条可执行规则**
7. **分享邀请** + **页脚**（含官方标志小图与「娱乐性解读」）

其余发现摊到**完整报告**里，不要挤成手机上读不清的仪表盘。

## 5. 生图提示词模板（中文）

把 `{}` 槽位按**这个人真实的数据**填。填不出依据的槽位就**整句删掉**，不要硬凑。

```
原创角色插画。主体是一份【{主食}】拟人化的小角色，造型严格参照官方餐品图
（该有的层要能一眼数出来，别画成尖顶有褶的包子）；它手里拿着【{饮料}】当道具，旁边有【{配餐}】作伙伴；
场景是【{环境}】。
美术方向：【{方向}】——风格、色系、笔触、背景都跟着这个方向走，不套用旧 A/B/C 的奶油白底。
角色居中，构图饱满，四周留白充足。
画面内不出现任何文字、字母、数字、标志或 logo。
```

> ⚠️ 这里**只说不要「包子」**（尖顶、有褶）。**不要**写「不要圆面包」——
> 麦香鱼、猪柳蛋麦满分这类汉堡的**上层面包本来就是光滑圆顶**，写反了会把正确造型一起否掉。

槽位取值规则：

| 槽位 | 取值来源 | 没有依据时 |
|---|---|---|
| `{主食}` | 出现笔数最高的 `staple` 或 `combo` 餐品 | 无 → 用本次观察里真实出现的那一口 |
| `{饮料}` | 出现笔数最高的 `drink`（带温度/糖分属性） | 删掉「手里拿着…道具」这句 |
| `{配餐}` | 出现笔数最高的 `side` | 删掉「旁边有…作伙伴」这句 |
| `{环境}` | `segment_freq` 里 ≥3 笔的时段 | 删掉「场景是…」这句 |
| `{方向}` | 在 G / H / I（或本人选定的其他方向）里挑一个填 | 本人未选定 → **不指定方向**，改出多组对照供其选 |

> **配色/背景不再写死**。旧版模板固定「主红＋金黄＋奶油白」只为旧 A/B/C 卡面服务；
> 角色插画的色系与背景由 `{方向}` 决定（见 §6.3），不要再用奶油白统一压平各组差异。

**禁忌**（写进任何提示词前自查）：

- ❌ 把薯条当通用装饰加给每个人
- ❌ 让模型画金拱门 logo
- ❌ 把官方餐品图直接拼进成品冒充插画
- ❌ 画面里出现文字/数字/假二维码/假认证章
- ❌ 把原始订单、姓名、地址、Token 放进提示词

**四条硬口径**（写提示词时照着做）：

1. **餐品按真实偏好选**，不由模板决定；画面里出现什么餐品必须有依据，**不要因为画了堡就顺手塞一包薯条**。
2. **表情由用户自选**：**无脸不是失败**，不笑也不是失败，**不许**因此自动补笑脸。只有**违背指定表情、肢体变形、品牌严重畸形、材质跑偏**才修（每张最多 1 轮）。
3. **材质必须一致**：短绒布、哑光、绒毛纤维与缝线可见。**薯条是绒条不是油炸薯条**、**可乐吸管是绒线不是硬塑料管**。
4. **形状锚点给对**：身体＝餐品本体的角色，**`image1` 必须是同餐品的官方餐品图**（`assets/brand/`）。
   早先把咖啡表情锚点放在 `image1`，薯条被带成咖啡杯身——这是踩过的坑。

**七种餐品必须一眼分得开**：三种汉堡分别是**高堆叠双饼（巨无霸）/ 蓬松炸衣绒球（麦辣）/
横扁光滑包＋宽扁不规则烤腿（板烧）**；板烧的肉必须**比面包更宽、两侧超出轮廓、一侧宽一侧窄、边缘起伏、
偏浅烤金棕**——写成「一片较扁的深棕色肉」就会出规整圆饼，和巨无霸的牛肉饼撞脸（踩过）；
可乐**没有杯盖**、有**深棕绒液面与绒线吸管**，与咖啡明确区别。

**边界**：21 只都是**原创美术角色**，不是实物、不做官方联名；**情绪不能从消费额／频次／订单时段推断**，
角色台词只是虚构台词，**不得**套回真实订单当结论。官方图上的广告文字／百分比／火焰标识**一律不抄**。

详版提示词、调用参数与修正口径见 `assets/style/plush-family/README.md` 与 `assets/style/plush-expressions/README.md`；
图鉴 `设计/毛绒角色图鉴-21角色.html`（项目内，不随包走；九角色阶段页 `设计/毛绒角色图鉴-九角色.html` 保留追溯）。

## 8. 个人分享卡（成品链路）

> **27 号起主入口更新**：确认 → `assign-visual`（保存回 profile，一次抽签永久）→ `export`
> （导出的胃已带主题）→ 按保存主题选参考、**整张 ImageGen** 出少字图形卡、核文字数字与图形。
> 下列 render-card HTML 流程**仅留兼容、不再主推**；本节其余内容作为方向史与口径保留。

事实与叙事都确认后，按这个顺序出卡——**用户只需要说一句话，不需要自己改 HTML，也不需要自己写提示词**：

1. **方向已定**：用**已选定的 I「被这一口治愈」**（§6.4）。除非本人另行指定，**不再让他重选方向**；
   需要手绘感时，**J（§6.5）已定版**，可作追加样式；**K（§6.6）与毛绒家族（§6.7）都没接 CLI**——
   毛绒家族只是**原创视觉演示**，**不能**说成已接入出卡，**也不预设选哪一支表情**。
   旧 A/B/C 与 D/E/F **均已否决、不再提供**；G/H 未选。
   渲染器里的 `--style A/B/C` 只是**旧版式布局**候选，与美术方向不是同一概念。
2. **拿到角色图**：读 `assets/style/approved-I/` 的风格锚点 → 用生图能力（WorkBuddy 的 ImageGen 已实测可用）
   按**这个用户已确认的可分享偏好**换主体餐品生成他的角色（通用提示词与空槽配方见 `approved-I/README.md`）。
   **只喂白名单里的偏好与聚合事实**；姓名、地址、Token、原始订单一律不喂。
3. **渲染**（I 为当前推荐）：
   ```bash
   python3 scripts/mcstomach.py render-card --card share-card.json --style I \
           --image ./我的角色.png --out ./分享/分享胃.html
   ```
   没有 `--image` 就输出**文字卡**，**绝不借包内参考图冒充某个人的专属角色**；
   卡内自带来源范围与样本局限，**截图之后仍然在**，不靠卡外附注。
4. **出图**：客户端有浏览器渲染/截图能力（WorkBuddy 已实测有）就把 `.card` 以 3 倍像素截成 PNG
   （常见约 1080 宽；内容长时**自然加长**，**不要为了凑 3:4 硬裁掉来源与邀请**）再分享；
   **没有生图 / 截图能力时如实降级**：给 HTML 或文字版，**不要谎称图片已经生成**。

产出的 HTML 是**单文件**：图片全部 base64 内联、零外链、`file://` 直接打开，手机 390px 宽也不横向溢出。默认**不带日期、金额、地址、订单 ID**。

## 11. 个性化条目：称号 / 昵称 / 城市装饰（28 号）

三个概念分开：**胃称号**（主标题候选，A 套参考 `persona-titles.md`）、**展示昵称**
（次级署名，回退链：麦当劳账户昵称→宿主明确昵称→询问本人；contactName/电话/设备名
一律不算）、**市级装饰**（城市从本人确认或配送地址市级解析，候选需认领；完整地址
只在内存，不落任何文件）。

**整图生图提示词入口**（不是只在文档里说一句）：跑
`mcstomach.py persona --profile … --out … [--context c.json] --print-image-prompt`，
把打印出的**个性化条目**拼进整张生图 prompt：

- 保持已确定主题（毛绒/像素），不重开设计评选；**plush 主题仅核心角色有毛绒质感**，
  背景/文字/统计图标是平面设计，整卡不做毛毡/织物纹理；
- 主标题＝已锁定类型或本人确认的饮料称号（`drink_title_main` 守卫，**全卡不出现第二个竞争主标题**）；
- 昵称作次级署名「{昵称}的麦门胃」，字号明显小于主标题；
- 已认领城市仅用于**内部选材**：挑 1—2 处地标/文化符号线稿或淡色融入背景边角，
  **合计约 5% 画幅、淡化处理**，不是立体摆件；**城市名称不上屏**（不写城市名/署名/角标）；
  它是地域装饰，**不证明此人爱吃当地菜**；没有可靠把握的元素就省略，不编造；
- 隐私禁项：完整地址、联系人姓名、电话、订单号、accountId 绝不进提示词；
  **昵称可上屏，城市名称不上屏**。

命名/城市/跳过任何一步都不改口味 facts/rules、不触发主题重抽；匿名分享可整体省略。

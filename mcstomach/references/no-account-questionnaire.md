# 备用问卷｜没有 MCP、没有订单时怎么走

> ⚠️ **这是备用入口，不是主流程。** 只有在 Step 0 接不上 MCP、或用户明确没有历史订单时才启用。
> 启用前**必须先讲明**：

> 「这个会话没接上麦当劳 MCP，我看不到你的真实订单。
> 我可以问你最多 5 个问题，也能做出一份胃——但**里面的依据是你说的话，不是订单算出来的**。
> 这一点会在最后那张卡上标出来，跟订单版不一样。」

**为什么必须讲明**：问卷不是数据。把问卷结果包装成「我从你的订单里发现」，就是欺骗——而且一眼假。

问卷版产出的 profile：`source.kind = "questionnaire"`，证据 `strength = "user_stated"`，卡片标「来源：你的自述」。

---

## 节奏

- **一轮最多问 2 题**，不要一口气甩 5 题。
- **总计最多 5 题**。
- **答过的不重复问**（记进 `asked_question_ids`）。用户已经主动说过的，直接从题单里划掉。
- 用户中途说「别问了，够了」→ 立刻停，用已有信息生成，并说明缺了什么维度。
- **语气是给胃做访谈**：轻松、具体、问能吃能答的。**不要硬编人格**，不要「你是一个灵魂自由的吃货」这种。

---

## 题单（按需要挑，不必全问）

### Q1 · 常点（`staple` / `side` / `drink`）

> 「说说你进麦当劳最常点的那一套——主食、配餐、喝的，各是什么？」

要点：一次收三个维度。用户只答一个就再补问一次，别拆成三题。

### Q2 · 不吃的（`hard_avoid`）

> 「有什么是你坚决不碰的？比如某些口味、某些食材——点了会不开心的那种。」

要点：**必须问**，因为这是唯一在推荐前会硬过滤的维度。问清是「讨厌」还是「不能吃」（过敏等）。

### Q3 · 不可妥协的一口（`must_have`）

> 「一顿麦当劳里，有哪一口是没了就感觉不对的？只能留一样的话，你留哪个？」

要点：**逼出单选**，才分得出主次。**不要说成「你最爱的食物是什么」**——太泛，收不到有效信息。

### Q4 · 价格与尝新取舍（`budget` / `novelty`）

> 「同一次点单，你更愿意把预算花在熟悉的那套上，还是拿去试个新品？」
> 「点单时你会为了便宜一点改主意吗，还是想吃什么就点什么？」

要点：**只问取舍倾向，不问收入、不问具体金额**。用户主动报金额可以记，但**不写进公开包**。

### Q5 · 帮别人点的情况（`roles`）

> 「你点单的时候，有多少是只给自己点的？有没有经常帮同事、家人一起点？」

要点：这条决定 `roles.profile_owner / payer / receiver` 能不能分开。
**帮别人点 ≠ 我喜欢吃**——这是画像归属的关键，也是主流程里代点歧义的兜底。**必须问**（除非用户主动说过）。

---

## 收完之后的处理

1. 把答案写进 `answers.json`，每条标 `source: "user_stated"`：

```jsonc
{
  "answers": [
    { "question_id": "q3", "dimension": "must_have",
      "text": "薯条，没了不行", "source": "user_stated" },
    { "question_id": "q2", "dimension": "hard_avoid",
      "text": "不吃香菜", "source": "user_stated" }
  ],
  "asked_question_ids": ["q1", "q2", "q3", "q4", "q5"]
}
```

2. 跑 distill / validate / export（同主流程 Step 3–4）。

3. **仍然要遵守**：
   - 样本门槛。自述不算订单笔数 → `personal_valid_orders` 按 0 计 → `sample.tier` 必然是 `snapshot_only` → **不给主类型、分享卡写「本次口味」**。
   - 「不吃香菜」这种明确声明可以直接作为 `hard_avoid`；但**不能**从自述推出「你是 XX 派」这种身份结论。

4. 卡片与 profile 上标注来源差异：

| 来源 | 卡片措辞 |
|---|---|
| `mcp_orders` | 「基于最近 N 笔有效订单」 |
| `questionnaire` | 「基于你的自述（未接订单）」 |
| `mixed` | 「基于最近 N 笔订单 + 你的补充」 |

---

## 与主流程的衔接

如果用户**后来接上了 MCP**：

- 重跑主流程，`source.kind` 变 `mixed`；
- 问卷答案**降级为补充**，不当订单证据；
- 已答过的题**不再重复问**——订单能算出来的就别问了。

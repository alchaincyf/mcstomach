# 揭晓脚本 A–F｜用户可见输出的唯一来源

> 适用：主流程 Step 2。**一次说完**，不挤牙膏。
> 前置：已跑完 `normalize`，手上有真实计数。

## 总原则

| 原则 | 含义 |
|---|---|
| 事实先站住 | 幽默可以放大事实的**意义**，不能放大事实**本身**。没发生的一律不写。 |
| 一条胜过十个形容词 | 挑**最大反差**那条，不是信息量最大那条。 |
| 一张卡一个身份 | 只给**一个主身份 + 一个小特点**。 |
| 笑点靶子 | 只能是「可爱的饮食坚持」。**禁止**身材、收入、疾病、人生、感情、消费水平。 |
| 认领不改数据 | 同一事实允许用户在两种措辞里挑一个，**数据不动**。 |
| 不造冲突 | 没分歧就展示一致；样本不足就说没数据——不拿「没数据」当「不合拍」。 |

## 0 · 先看来源状态，再决定说什么（v2）

**开 A 段之前先读 `source_state`。** 说不出口的状态就别硬编故事：

| `source_state` | 开场必须怎么说 | **禁止**说什么 |
|---|---|---|
| `not_connected` | 「这次没连上你的账号，我们走自述那条路。」 | 不许装作读到了订单 |
| `fetch_failed` | 「接口这次读失败了，**不能**当成你没有记录。」 | ❌「你账号里没有订单」 |
| `empty_account` | 「这次接口没有返回订单记录。」→ 转自述版 | 不许把没读到说成「你没点过」，也不许因为 0 单就什么都不给 |
| `no_valid_samples` | 「读到 N 笔，但都还不能算你的（取消／状态读不出／疑似代点）。」 | ❌ 不许拿这些单生成稳定类型 |
| `single_order` | 「只有 1 笔能算是你的 —— 就说说这一次。」 | ❌ 不许给主身份/外号 |
| `stale` | 「最近一笔可见下单在 {days_since} 天前，这份口味档案有点旧了 —— 要不要按最近的更新一下？」 | ❌「你已经不吃麦当劳了」 |
| `normal` | 正常走 A–F | — |

- **0 单 + 本人自述** → 自述版也要产出**有名字、有宣言、有下次规则**的完整胃，并标 `naming.source = "user_stated"`。
- **1 单** → 必须把餐品细节（`observations`）带进个人胃；候选档写「初见」，并注明「样本还少，尚不构成稳定偏好」。
- **老档案** → 输出旧口味档案并**邀请更新**；`sample.stale_archive == true` 时这条发现要出现在 `narrative.discoveries` 里（讲「距今 N 天」），不能被别的发现挤掉。

## A · 开场：只报样本 + 一条反差

```
读到最近 N 笔麦当劳订单（其中 M 笔已取消，不算）。
[最大反差的一句话事实]
```

`N`/`M` **必须来自 normalize 的真实计数**。

反差优先级：① 「主食换了 X 种，某个配餐一次没落下」→ ② 「同一餐品连续出现 N 次」→ ③ 「集中在某个时段」→ ④ 「金额区间很稳/很散」（**只说区间，不谈消费能力**）。

**边界**：`order-list` 上限 10 笔且是「近期」。措辞必须是「读到最近 N 笔」，**不能**写「你一共点过 N 次」。取消单要说出来，但不逐个念。

---

## B · 一句胃的自述

紧贴 A 的事实，**一句话**。

**通过**（事实：主食换 3 种、薯条没落下）：
> 「主角换了一轮又一轮，薯条从头坐到尾。」
> 「本胃已对薯条设置默认勾选。」

**不通过**（订单里没证据）：
> ❌「你一定常加班到深夜」— 推断作息职业
> ❌「看得出你在控制预算」— 推断收入
> ❌「你偷偷把朋友的薯条也吃了」— 编造行为

判据：**这句话能不能被那笔订单证伪？** 证不了就改到能。

## C · 类型：够了才给

**门槛**：`personal_valid_orders ≥ 3`（可归于你本人的有效订单）**且存在重复模式**。

| 情况 | 给什么 |
|---|---|
| `type_ready` | 1 个主类型 + 1 个习惯标签 + 2~3 条依据 |
| `snapshot_only` | **只描述本次真实出现的那一口**，明说「样本还不够，还谈不上稳定类型」。**不给身份、不给外号、不给「单品唯粉」这类锚定结论。** |

外号**最多两个同义候选**，让人认领或自己起；要能自然接在「我是……」后面。

### 候选命名种子（原创，非用户真实结果）

| 种子 | 触发依据（**必须在订单里可核实**） |
|---|---|
| 麦门早八生 | 订单时间集中在早餐窗口（05:00–10:30） |
| 薯条常驻嘉宾 | **订单里确实有「薯条」类餐品**（`productName` 含「薯条」），且它在多笔订单重复出现，同时主食在多变 |
| 菜单钉子户 | 同一**具体餐品**（归一后同名）在多笔订单重复出现，且主食基本不换 |
| 单品唯粉 | 高频重复**单一**餐品，几乎没有别的选择（品类数 ≤ 3） |
| 固定搭档 | **两道**餐品同频出现（同一出现笔数），且都接近「每单都有」 |

**硬约束**
- **同频要当组合，不要压成单品。** 麦乐鸡和橙汁都是 3/3 时，不许写成「只爱橙汁的单品唯粉」——那是固定搭档 / 组合偏好。
- **不是所有人都要套这几个之一。** 证据支持别的贴切短名就用别的；脚本给的是**有依据的候选**，本人认领了更好的说法就以本人的为准（`naming.locked`）。
- **「薯条常驻嘉宾」必须真的是薯条。** 如果反复出现的是苹果片、玉米杯、可乐等**其他**配餐：**不许**用带「薯条」字样的外号——要么换成贴切的名字（如「苹果片钉子户」），要么只描述事实不给外号。
- **「新品巡逻员」必须有新品身份依据**（订单里出现可识别的新品类/限定品）。**餐品多样不算尝新**，不能给。
- **命名与宣言必须绑同一批证据 ID 和计数**（`naming.evidence_ids` = `self_statement.evidence_ids`）。**不是每一单都出现，就不许说「从头坐到尾」。**
- 每个命名下面写明**触发它的那条依据**（指向 rule id 或统计量）。
- 必带免责：昵称是**娱乐性解读，不是人格诊断**。输入是订单不是问卷，**不能套四字母心理学维度**。

### 分类识别不出来也要有结果

关键词表是启发式的。识别不出类别的餐品**保留原名，按具体餐品名的重复次数照样揭晓**——不能因为分不出「主食还是配餐」就不给有趣结果。**没点过不等于不喜欢**：缺失就保持未知，硬忌口只能来自本人明确声明。

## C+ · 叙事：主身份 ＋ 次特点 ＋ 发现 ＋ 相处说明 ＋ 下次规则（v2）

`narrative` 由脚本从真实事实生成，**再允许模型／本人改写措辞**。结构固定，但**味道不锁死**：

| 槽 | 要求 |
|---|---|
| `primary_identity` | 主身份（= `naming.primary`）。`snapshot_only` 时留空，只说「本次口味」 |
| `secondary_trait` | **必须落在另一个维度**上，且与主身份有真张力（主食多变 → 饮料专一）。**没有就不给。** |
| `discoveries` | **有几条给几条，最多 5 条**。每条必须带 `text` + `evidence`（+ 能指向规则时给 `evidence_ids`） |
| `getting_along` | 胃的相处说明：怎么跟这个胃相处 |
| `next_order_rule` | 下一次点单规则，一句可执行的话 |

**几条铁律**

- ❌ **绝不为了凑「2～4 条发现」编数据。** 只有 1 条就写 1 条。`validate` 会查 `discoveries` 每条必须带 `text` 与 `evidence`。
- **同维度只留第一条**（发现按维度去重）：久了没下单（`recency`）和下单结构（`session`）是**两回事**，不会互相顶掉。
- 次特点不许和主身份同一个维度，不然就是重复说一遍。
- 事实由脚本算；**模型只换说法，不换事实**。

**写回**（模型或本人改了昵称/宣言/故事）：

```bash
python3 <SKILL>/scripts/mcstomach.py narrative --profile profile.json --narrative new.json --out profile.json
```

- `evidence_ids` 指向**真实存在的规则 id**；悬空 → **整条拒绝**（返回 `{"error": …}`），画像不变。
- 写回后 `narrative.source` 变 `model` / `user`；本人改写时 `naming.locked = true`，旧名进 `candidates`。
- 键名是 `display_name`，不是 `name`。

## D · 核对点：只在有歧义时追问

| 歧义类型 | 信号 | 问法示例 |
|---|---|---|
| 代点/团体单 | 单 sku quantity≥3、品类数≥5、总份数≥6 | 「X 月那笔点了 4 份【A】，你自己吃的还是帮人带的？」 |
| 默认套餐 | 某组合一直以默认形态出现、无替换记录 | 「这套餐是按默认配的，还是里面有哪样你特意换过？」 |
| 时间/场景 | 时间落在可解释窗口、或与自述不符 | 「这几笔都在早上，确认是你本人在吃？」 |
| 状态未知 | 存在 `status_unconfirmed` 订单 | 「有一笔状态我这里读不出来，你记得是吃上了吗？」 |

**无歧义 → 不问，直接请用户确认画像。**
**顺序铁律**：**绝不**先问「你常点什么」，再宣布「我从数据里发现你常点 X」。

一轮最多 2 题，总计最多 5 题，**答过的不重复问**。

## E · 确认后：私密胃 + 公开分享卡

一次交五件：`profile.json`（私密）、个人胃 `SKILL.md`（可交给自己的 AI）、`CERTIFICATE.txt`（可复制）、`share-card.json`（公开）、`报告.md`（私密完整版）。
**私密报告里可以有日期；公开卡一律不含日期、金额、门店、订单号。**

### 分享卡四件

1. **类型位**
   - `type_ready` → 主类型（+ 可选习惯标签）
   - `snapshot_only` → **只能写「本次口味」**，并标注「样本不足，还谈不上稳定类型」。**禁止**在这里塞主类型。
2. **胃的宣言**：B 那段，或同事实的另一措辞。
3. **一条脱敏聚合证据**：如「近 6 笔可归于本人的订单里出现 6 次」——**计数可以有，原始时间/地点/金额没有**。
4. **来源范围 + 召唤朋友**：「基于最近 N 笔有效订单」＋「把你的胃发来，看今晚谁迁就谁。」

### 积分等级

- 用户自选**是否公开计数**；**默认只显示称号**。
- 必标：**娱乐段位，非官方评级，阈值公开可复算**。
- **积分未知 → 「待认证」**，不塞低等级。
- 阈值表见 `portfolio-schema.md`。

## 完整输出样例（⚠️ 虚构示例）

> 以下数字为**虚构 fixture**，用于示范结构与措辞边界，不代表任何真实用户。

```
读到最近 10 笔麦当劳订单（其中 2 笔已取消，不算）。
7 笔可归于你本人，主食换了 3 种，薯条一次没落下。

【B】主角换了又换，薯条从头坐到尾。

【C】主类型：薯条常驻嘉宾
     习惯标签：主食自由派
     依据：① 7 笔本人订单里薯条出现 7 次
          ② 其中 5 次是你单独加点的，只有 2 次是套餐自带
          ③ 同期主食分别是 3 种不同的
     外号候选：「薯条常驻嘉宾」/「薯条赞助商」——认领一个，或者两个都不要。
     注：娱乐性解读，不是人格诊断。

【D】有一笔点了 4 份【麦辣鸡腿堡】——是你自己吃的，还是帮同事带的？

【E】你点头之后我生成完整胃，再给你一张能晒的卡。
     段位：待认证（积分字段这次没读到，不猜）。
```

**对照：样本不足时（`snapshot_only`）**

```
【C】只有 2 笔可归于你本人，还谈不上稳定类型。
     本次口味：你点了【A】和【B】，两次都带了薯条（其中一次是单独加点的）。
     等订单多一些，我再给你一个能认领的身份。

【E】分享卡类型位写「本次口味（样本不足）」，不给你安一个主类型。
```

# 点餐推荐 · 两人合拍 · 用餐反馈

---

## §1 用户说「饿了」

**先过滤硬忌口**：把所有 `kind = hard_avoid` 的规则先套一遍，命中即移除，**不解释、不劝、不替代成相似品**。

**然后给三个可选项**，各自标明属于哪一档：

| 档 | 含义 | 怎么选 |
|---|---|---|
| **熟悉** | 复刻订单里反复出现的组合 | 取 `confidence: high` 且重复出现最多的规则组合 |
| **小变化** | 熟悉的基础上换一样 | 固定住最高频的那一两样，替换一个次要项（配餐或饮品） |
| **尝新** | 引入用户没点过或极少点的品类 | 仅在订单里出现过「愿意尝新」证据、或用户本次明确说要尝新时才给 |

**不足三项就如实少给。** 「你的硬忌口比较多，能给的只有两项」——比硬凑第三项诚实，也比硬凑有用。

### 必须标「待查」的

没有实时菜单、价格、热量数据时：

- 价格一律标 **待查**，**禁止**发明「到手价」「约 XX 元」
- 热量/营养没调 `list-nutrition-foods` 就标 **待查**
- 门店是否有货没查 `query-meals` 就标 **待查**
- 可以说「这家店今天有没有这个，得看菜单」

### 当前功能版停在推荐

**本 skill 不下单。** 用户真想下单时，把话说全：

1. 明确**门店**
2. 明确**取餐方式**（到店自取／外送／得来速／团餐）
3. 列出**明细**（每一项 + 数量）
4. 用 `calculate-price` 拿到**最终试算价**（工具返回单位是**分**，展示要除以 100 转元）
5. 把以上四项摆给用户，**等明确确认**

确认之后才谈得上下单；本轮不做。

## §2 用户说「我们的胃合不合」

**只用双方共同已知的维度比较。**

### 比较流程

1. **取交集**：列出两边 profile 里**都**有数据的维度（例如两边都有 `side`、`drink` 规则）。只比这些。
2. **逐维度出结论**，三种结果：
   - **合拍**：两边同向（都爱某个配餐 / 都不吃某类）
   - **分歧**：两边明确相反（一个有 `hard_avoid`，另一个常点它）——**只展示一个真正有分歧的**，不刷屏
   - **说不准**：某一边该维度是 `low` 置信度或缺数据 → 标「样本不足，说不准」
3. **样本不足就明说**：如果交集为空或很小，直接讲「你们俩的数据覆盖的维度几乎不重叠，这份比较说明不了什么」。
4. **不给百分比。** 不许出现「合拍度 87%」「灵魂契合指数」这类**神秘百分比**。没有全量用户库，也没有统计模型支持。要形容就用**离散的事实条数**：「4 个共同维度里 3 个同向」。
5. **不做恋爱关系判断。** 不评价「你们该不该在一起」「谁更爱谁」。只讲吃。
6. **没有分歧就展示一致**——**不为好玩制造冲突**。也**不拿一边缺数据当「不合拍」**。

### 折中：给一道双方都能吃的

在交集上找一条两边都不违和的思路，输出一句可执行的建议。例如：

> 「你俩都吃鸡，也都能接受无糖可乐——点一份鸡类主食分着吃，再各要一杯饮料；薯条只点一份，谁吃谁拿。」

**不做**：声称这是最优解、保证好吃、替代门店库存确认。

## §3 用户说「吃完了，不太对胃口 / 还行 / 下次换一个」

**增量更新，不推倒重来。**

| 反馈强度 | 处理 |
|---|---|
| 单次负面（「这次不好吃」） | 给相关规则加一条 `history` 记录，`confidence` **最多降一级**，**不改变 `text`** |
| 明确表态（「下次换一个」） | 追加一条 `kind: constraint` 的新规则，**旧规则保留为 `active`**，标注冲突 |
| 同方向累计 ≥ 3 次 | 才允许把原规则降级/退休 |

**铁律**：

1. **保留原依据**：原 `evidence` 不动，新记录追加到 `history`，写明时间、内容、来源。
2. **不能一顿饭抹掉全部偏好**。一顿不对胃口 ≠ 这个人变了。
3. **`hard_avoid` 只能由本人明确声明才可新增**，不能从一次「不好吃」推出来。
4. **冲突要摆出来**：新反馈和旧规则冲突时，写明「你的旧记录显示…这次你说…」，让本人裁定。
5. 更新后**重新 `validate`**，再看要不要重新 `export`。

命令：

```bash
python3 scripts/mcstomach.py feedback --profile profile.json \
  --rule-id r_side_fries --signal negative --note "今天没那么想吃薯条" --out profile.json
```
